# 再来一条 / One More Take

36 秒、30 fps、540×960，无音频叙事样片；源文件为 `examples/one-more-take.json`。
目的是验证现有动作库能否表达“口令 → 错误反应 → 纠正 → 包袱”，而不只展示独立动作。

| 时间 | 构图 | 剧情 | 复用能力 |
|---|---|---|---|
| 0–6 秒 | 双人 | 到场、确认准备 | 位移、walk、wave、nod |
| 6–12 秒 | 双人 | 约定听口令挥手 | idle、nod、视线 |
| 12–18 秒 | 双人 | Bolt 说鞠躬，Pixel 挥手 | wave、suspicious |
| 18–24 秒 | Bolt 近景 | 纠正；Pixel 从画外辩解 | 近景、画外字幕、视线 |
| 24–30 秒 | 双人 | Bolt 改说挥手，Pixel 鞠躬 | bow |
| 30–36 秒 | 双人 | 喊停，Pixel 问是否再来一条 | nod、wave、look_down |

## 制作约束与修改

- 六个镜头显式重复到场后的舞台偏移，切镜时保持位置；近景 camera 显式补偿主体偏移。
- 台词与动作分时，错误动作留出无字幕的观看间隙。所有时长直接写进已有 performance 区间。
- 字幕保持短句，使用已有固定覆盖层；没有音乐、配音或口型。
- 第一版能力 demo 暴露出双腿趋于重合的问题。本片使用后端 0.6.1 的交替抬脚和屈膝，沿用 v0.6 的 walk 动作语义，不增加骨骼、碰撞或脚步锁定系统。
- 修改范围只涉及后端步态绑定、一个新故事 JSON 和测试；没有给剧情硬编码专用播放器逻辑。

## 验收

- Python 校验故事、切镜位置连续性，并验证步态端点和左右交替；Node 对比整数与半帧采样。
- Chromium 检查抬脚几何、口令/错误动作/近景/包袱的时间线，反向定位与重播时比较同帧像素。
- 导出直接调用 `StickFigureBackend.frame()` 生成 SVG，经 librsvg/Cairo 栅格化和 FFmpeg 编码。
- 样片为实际程序输出；不同字体和栅格化器之间不承诺逐像素等同。叙事效果仍需观众反馈，没有将自动化测试等同于好看。

该样片是三集 30–60 秒目标中的首支候选，尚未做配音和家庭观众测试；不把内容验收或完整 M1 标为完成。
