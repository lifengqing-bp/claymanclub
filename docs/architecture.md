# 后端无关架构

## 三层边界

| 层 | 拥有什么 | 不应包含什么 |
| --- | --- | --- |
| Story | 角色身份、场景语义、对白、动作、情绪 | SVG 坐标、骨骼、引擎对象 |
| Presentation plan | 整数帧时间线、构图范围和主体、相对摄像机轨迹 | Unreal 机位路径、特定渲染指令 |
| Backend | 能力清单、实体绑定、布局、动作映射、具体输出 | 改写故事意图的隐式降级 |

当前 Story 与 Presentation plan 存放在同一份版本化 JSON（v0.5 视线/点头、v0.4 表演时间、v0.3 运镜、无轨迹 v0.2） 中，不为规模尚小的项目引入多余服务。

## 最小后端接口

`PresentationBackend` 定义 `name`、`version`、`capabilities`、`preflight(episode)` 和 `render(episode, output) -> RenderResult`。

核心先检查故事结构，再由后端检查能力和资源绑定，最后才创建输出。RenderResult 返回入口及 manifest 路径，不暴露 Sequencer、SVG DOM 或其他引擎类型。当前接口为同步本地调用；任务队列、进度和取消后续按真实需要添加。

`Capabilities` 声明动作、情绪、构图、角色数上限、输出格式及 camera_spaces / camera_interpolations / timed_performances / gaze_targets / animated_actions。新能力默认关闭（空集或 false），旧适配器不会自动获得运镜支持。通用管线先检查摄像机能力，后端 preflight 也检查直接调用路径。复杂的动作前提及资源可用性由 preflight 检查。音频等新特性加入协议时必须显式扩展能力协商，不从后端名称推断。

## 语义与资产分离

`examples/catalog.json` 是故事词汇，不是模型资产清单。逻辑角色 bolt 在火柴人后端是程序绘制的线条，在 3D 后端可以是一个模型。它没有全局 planned/ready 状态；可用性属于具体后端的绑定。

火柴人后端已实现 robot_lounge 的简化背景，角色采用程序绘制。Unreal 真实资产绑定尚不存在。未来适配器须记录版本和授权，并拒绝未就绪绑定。

构图使用 `framing: {size, subjects}`。火柴人将 close 映射为单人画面；3D 可映射为摄影机取景。camera 使用相对于基础构图的右手坐标、以参考画面高度为单位的位移、角度和缩放。核心不规定焦距、引擎世界坐标或骨骼；后端高级选项应存放在独立配置中。

## 后端状态

| 后端 | 状态 | 产物 |
| --- | --- | --- |
| stickfigure | 已实现 | SVG 首帧快照、支持定时姿势切换和二维运镜的 HTML 分镜、manifest |

| 其他 2D/3D/文本形式 | 扩展点 | 由实现者声明 |

测试中的 TextBackend 是隔离性测试替身，不是正式发布的文本后端。

## 能力差异

默认严格失败，不静默丢失动作。当前火柴人是粗略分镜表现：v0.2–v0.4 的 nod 只画低头关键姿势；v0.5 才执行一次程序化头部下移/回正。这个限制写入 manifest 和预览页面。未来若需要把复杂表演降级为简化表现，应输出明确的降级计划并由用户审核。

## 可重复与故障边界

静态产物可重复生成，manifest 记录规范化故事摘要及后端版本。浏览器按墙钟推进帧号，每次绘制使用 floor 后的绝对帧，镜头内从关键帧重新采样摄像机状态；暂停或反向拖动不依赖此前播放历史。这不是帧精确视频编码。完整跨镜头连续表演、配音时长、资源摘要、引擎模拟缓存及局部重拍尚待实现。

当前预检在创建输出前完成；写盘失败可能留下不完整目录，应换用新输出目录重试。尚未实现事务提交、并发调度或恢复机制。

## 摄像机实现边界

`camera.py` 负责协议校验、能力协商及纯函数 `sample_camera`。`framing_3d` 是可校验的扩展语义，火柴人严格拒绝；不创建 Unreal 接口或三维渲染系统。

火柴人将相对摄像机姿态映射到 SVG 场景组的逆变换。基础画面高度为 960，因此一个位移单位映射为 960 个后端布局单位；这是后端实现细节，不进入 Story JSON。标题与字幕在场景组之外。`frame(..., local_frame)` 可生成任意时刻的确定性快照。

生成的 HTML 内嵌可信渲染器生成且经过转义的 SVG 与轨迹，无网络请求、第三方包或 SVG 内部独立动画时钟。`player.js` 用同一插值规则从绝对帧求值。Python 测试覆盖协议和输出；可选 Node 内置 VM 测试运行实际生成的播放器，逐帧比对 Python 采样，并验证播放、暂停、拖动、切镜和重播。Node 仅用于开发验证，Python CLI 与生成页面均不依赖 Node。

## 表演时间实现边界

`performance.py` 负责半开区间校验、同演员冲突检测、能力预检和无历史采样。
火柴人只为不同表演边界生成状态，播放器切换 SVG 后重新应用当前帧的摄像机变换。
状态数由表演边界数量决定，不随镜头总帧数增长。默认姿势、字幕与颜色仍由后端负责。
v0.4 为离散表演调度；v0.5 增加有限的程序化头部动作，仍不是骨骼动画、音频同步或完整连续动作系统。

## 视线与点头边界

核心只保存 gaze_target 角色引用与归一化点头相位；水平舞台布局、眼睛偏移和头部下移幅度属于火柴人绑定。
仅表演边界创建 SVG 状态，每帧更新头部组的绝对 transform，随后由父场景组承载摄像机变换。
Python nod_amount 与 JavaScript nodAmount 有逐帧和半帧采样一致性测试；真实 Chromium 覆盖动作像素、暂停、反向拖动、字幕隔离和重载。
