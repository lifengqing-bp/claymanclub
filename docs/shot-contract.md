# 表现计划 v0.6

引擎无关的分镜协议。v0.5 增加显式视线目标和连续点头，继续兼容 v0.2/v0.3/v0.4。v0.4 新增逐项表演区间，继续兼容 v0.2/v0.3。v0.3 新增可选 `camera` 轨迹；继续接受无 camera 的 v0.2，保持原有静态构图。v0.1 及未知版本拒绝。这里的 camera 是新协议，不是恢复 v0.1 的旧摄影机字段；v0.2 携带 camera 也拒绝，防止静默丢失意图。

顶层字段：schema_version、episode_id、fps、duration_frames、scene、cast、shots。
每个镜头：id、start_frame、end_frame、framing、performances，以及可选 camera。
每项表演：actor、action、emotion、line。line 可为空字符串。

`framing` 包含：
- `size`：wide 或 close。
- `subjects`：本集角色 ID 列表；close 恰好一个主体。

帧区间为 [start_frame, end_frame)，镜头连续、无重叠，完整覆盖 duration_frames。角色及词汇必须在目录中；后端还需另行检查是否支持。

## 摄像机轨迹

```json
"camera": {
  "space": "framing_2d",
  "interpolation": "linear",
  "keyframes": [
    {"frame": 0, "position": [0, 0, 0], "rotation": [0, 0, 0], "zoom": 1},
    {"frame": 90, "position": [-0.08, 0.05, 0], "rotation": [0, 0, 5], "zoom": 1.2},
    {"frame": 180, "position": [0.08, 0, 0], "rotation": [0, 0, -5], "zoom": 1.1}
  ]
}
```

这段示例已用于 episode-001 的第一镜头。它先移向左上方主体并放大、轻微旋转，再向右移。轨迹描述摄像机姿态，场景采用其逆变换；不是移动角色。

### 坐标与取景基准

- `framing` 先确定基础构图；camera 在整个镜头内相对于这个固定基准求值，不每帧重新自动取景。
- `space` 支持 `framing_2d` 和 `framing_3d`。两者共享右手坐标系：原点在基础画面中心，+X 向右，+Y 向上，+Z 朝向观看者；初始观看方向为 -Z。
- `position` 是摄像机相对于基准的 `[x, y, z]` 位移。一个单位等于基础构图参考平面的可见高度，三个轴使用同一长度单位，非像素、米或引擎世界单位。后端负责映射到自己的布局。
- `rotation` 是 `[x, y, z]` 欧拉角，单位为度，正方向遵循右手规则。摄像机姿态矩阵为 `Rz(z) Ry(y) Rx(x)`（列向量，先 X 再 Y 再 Z），视图使用逆姿态。二维只使用 Z 角度；摄像机正 Z 旋转时画面内容顺时针旋转。
- `zoom` 为相对于基础构图的正倍率：1 保持基准，2 表示图像放大两倍。它不隐含沿 Z 轴移动，也不是某种引擎的焦距参数。
- `framing_2d` 要求 position.z、rotation.x、rotation.y 恒为零。非零必须使用 `framing_3d`，不可偷渡到二维轨迹。
- `framing_3d` 保留三轴位移和旋转的相对姿态语义；本版没有任何支持它的正式后端，也不定义透视镜头、焦距、景深、look-at 或轨道系统。后续三维后端必须声明能力并明确基础构图与投影映射。

### 时间、插值与边界

- `frame` 为相对镜头起点的整数帧号，不是秒或整集绝对帧。
- keyframes 非空，首帧必须为 0；后续严格递增，无重复，范围为 `[0, end_frame-start_frame]`。
- 可以在镜头排他结束边界放置一个插值目标，但播放器不显示该镜头的结束边界帧；此时切换到下一镜头的局部帧 0。单帧镜头同样适用。
- 仅支持 `linear`：position、rotation 各分量及 zoom 均线性插值。角度不自动取最短路径、不取模；0→360 表示完整一圈。
- 只有一个关键帧表示静止；末关键帧早于镜头结束时保持其值。通用采样器在首/末关键帧之外夹取端点值。
- 每个关键帧必须完整给出 frame、position、rotation、zoom；不继承遗漏值。camera 与关键帧内的未知字段拒绝。
- position/rotation 必须各含三个有限数值，绝对值不超过 1,000,000；zoom 范围 `[0.000001, 1000000]`。这些数值边界避免后端变换溢出。布尔、字符串、NaN、Infinity 均拒绝。
- 缺省 camera 等价于零位移、零旋转、zoom=1；跨镜头不继承状态。

## 能力与执行

`Capabilities.camera_spaces` 与 `camera_interpolations` 默认均为空。通用管线在创建输出前检查轨迹所需能力，后端 preflight 再检查具体绑定；不能忽略不支持的轨迹。火柴人声明 `framing_2d` 和 `linear`，任何 framing_3d（包括零姿态）均明确拒绝。

火柴人 HTML 用绝对播放帧定位镜头，再以局部帧采样轨迹；播放、暂停、拖动和重播都走同一个求值路径，不累计增量变换。画面场景与角色一起运镜，标题和对白保持在屏幕坐标。独立 SVG 文件是局部帧 0 的静态快照；manifest 保留轨迹，HTML 执行运镜。

v0.2/v0.3 表演在整个镜头中用一个关键姿势代表，同一演员每镜头最多一项。v0.4/v0.5 使用下述时间区间。尚无音频同步、道具或通用连续姿态系统。

后端布局、程序图形、真实模型、材质、骨骼和引擎 API 不属于本协议。后续通过版本化后端配置和逻辑 ID 绑定扩展。

## v0.4 表演区间

每项 performance 必须包含 `start_frame` 和 `end_frame`，其余 actor、action、emotion、line 字段不变。

```json
{"actor":"bolt","action":"idle","emotion":"surprised","line":"等等……","start_frame":120,"end_frame":170}
```

- 时间是镜头局部整数帧，区间为 `[start_frame, end_frame)`，必须满足 `0 <= start < end <= 镜头长度`；布尔值不接受。
- 同一演员可以出现多次，但区间不得重叠；相邻区间合法。不同演员可以同时表演。列表不要求按时间排序；同时出现的对白按输入列表顺序显示。
- action、emotion、line 在同一区间生效，结束时不延续。演员在空档回到 idle/neutral 且不显示对白；镜头仍须包含至少一项表演。
- 字幕仅在表演区间显示。时间字段不代表音频剪辑，也不推算语速。
- v0.2/v0.3 不接受 performance 上的时间字段，避免静默忽略。它们仍保持整镜头静态姿势与对白。
- v0.4 摄像机字段沿用 v0.3；无 camera 时仍为恒等变换。切换姿势后按当前局部帧重新采样摄像机。
- `Capabilities.timed_performances` 默认 false。通用管线及火柴人直接 render 都在输出前预检；未声明支持的后端拒绝 v0.4。
- 火柴人按表演边界预生成 SVG 状态，而不是每帧生成一张 SVG。HTML 按绝对帧选择状态；反向拖动、切镜、重播不依赖历史。独立 SVG 仍为镜头局部帧 0 快照，manifest 保留表演区间。

v0.4 为离散姿势切换，nod 保持低头关键姿势。v0.5 的 nod 语义见下文。

## v0.5 视线与连续点头

v0.5 沿用 v0.4 的半开表演区间和 v0.3 的摄像机轨迹。

- 可选 `gaze_target` 是另一名 cast 成员的 ID。未知角色、自身、非字符串均拒绝；v0.2–v0.4 携带该字段也拒绝。
- `gaze_target` 在表演区间内生效，可与 idle、nod、look_at_partner、wave、bow 组合；与 look_down 冲突并报错。无目标时保留原动作的视线语义。
- 目标不必出现在 close 构图里。火柴人按固定舞台绑定（cast 顺序从左到右）选择水平视线方向；近景保持这个方向。当前不支持点坐标、道具、移动目标或平滑转眼。
- v0.5 的 nod 在区间内完成一次平滑低头/回正，至少 3 帧。首帧 start 与最后显示帧 end-1 均为中立；半开结束帧不再执行该表演。
- 归一化动作强度为 `(1 - cos(2*pi*u))/2`，其中 `u=(frame-start)/(end-start-1)`；端点外为零。火柴人将强度映射为最多 15 布局单位的头部下移，眼睛与嘴同步移动，身体不动。这是程序化头部动作，不是骨骼动画。
- 区间有奇数帧时中间帧达到最大强度；偶数帧的峰值位于两帧之间。速度由区间长度决定，不循环。
- v0.2–v0.4 的 nod 仍是静态低头姿势，不因后端升级改变语义。
- `Capabilities.gaze_targets` 默认 false；`animated_actions` 默认空集。实际使用 gaze_target 或 v0.5 nod 时检查相应能力，拒绝发生在输出前。
- Python 快照和 HTML 播放器使用相同纯函数规则；动作不使用 CSS/SMIL 独立时钟，也不按历史累加位移。动作先在角色内部求值，再随场景应用摄像机变换；字幕仍在固定覆盖层。

示例：`examples/gaze-and-nod.json`。本版还支持下述 wave/bow；跨动作混合、行走和空间移动尚未实现。

## v0.5 动作词汇扩展：wave / bow

无需新增字段，`action` 可以使用 `wave`（挥手）或 `bow`（鞠躬）。只接受 v0.5，且后端必须在 actions 与 animated_actions 中声明对应动作，不能退化成静态 idle。同演员表演仍不得重叠。

- wave 至少 17 帧：抬起画面右侧手臂、往返摆动、放回；首帧及最后显示帧回到中立。最小时长避免摆动在稀疏帧采样下完全消失。
- bow 至少 3 帧：一次上身前倾并回正，腿部不变；首末显示帧中立。当前火柴人绑定为绕腰向画面右侧最多旋转 30 度，与 gaze_target 独立。
- 所有幅度、关节点和角度属于后端绑定，不写入故事。火柴人头部、上身、右臂分别建组，腿部在上身组之外；整个人物仍位于摄像机场景组内。
- 表演切换、空档、切镜都重新从当前帧取状态；不会继承上一动作的关节旋转。emotion 和 gaze_target 在整个动作期间有效。
- wave/bow 是有限的程序化动作，不包含骨骼、走路、脚步 IK、道具抓取或空间位移。

火柴人 wave 映射：令 `u=(frame-start)/(end-start-1)`、`a=(1-cos(2*pi*u))/2`，`l=min(1,4*u,4*(1-u))`，则右臂角为 `-120*l*l*(3-2*l)+20*sin(8*pi*u)*a` 度；区间端点外为零。抬手平台期间含两个摆动周期。bow 角为 `30*a` 度。Python 与 JS 对整数及半帧采样做一致性验证。


## v0.6 舞台位移与 walk

v0.6 继承 v0.5 的定时动作、视线与摄像机；旧版保留原有行为。
每个镜头可带 `actor_tracks` 列表，每个演员最多一条轨迹；缺省或空列表代表所有演员零偏移。

```json
"actor_tracks": [{"actor":"bolt","space":"stage_2d","interpolation":"linear",
  "keyframes":[{"frame":0,"offset":[0,0,0]}, {"frame":120,"offset":[0.09,0,0]}]}]
```

- offset 是相对演员固定舞台绑定的三轴位移，不是相对上一帧。右手坐标 +X 向右、+Y 向上、+Z 朝观众；单位为后端固定舞台参考高度，与摄像机 zoom 和当前 close/wide 构图无关。故事不携带像素、关节或引擎对象。
- `stage_2d` 要求 Z 为零；预留 `stage_3d`，当前火柴人明确拒绝，包括全零三维轨迹。`Capabilities.actor_spaces` 缺省为空；渲染前检查。
- keyframes 非空，首帧为 0，局部整数帧严格递增，最大可到镜头排他结束边界。仅 linear；首末之外夹取并保持端点。三轴必须为有限数值，绝对值不超过 1,000,000。布尔、未知字段、重复演员、未知演员均拒绝。
- 轨迹与 performance 独立：空档继续保持位置，允许边挥手边位移；位移不会自动选 walk。同演员动作仍不得重叠。切镜不继承轨迹，需显式给出下镜初始位移以维持位置。
- 火柴人映射一单位为 960 布局单位；wide 静态 X 绑定为 170/370（单演员 270），close 显示主体基点 270，偏移始终基于固定绑定，不自动追踪。名字随角色位移；字幕、标题、控件固定。视线比较全体演员的舞台 X，包含近景外演员；左右交换会反向，同 X 时正视。当前仅水平视线，不模拟深度遮挡或碰撞。
- `walk` 仅 v0.6，至少 17 帧，须有 animated_actions 能力。表演区间内完成两个平滑步态周期，首帧与 end-1 回中立；位移独立求值。原地走合法，长距离可能滑步，不承诺物理步长或脚部锁定。
- 火柴人步态绑定：`22*sin(4*pi*u)*(1-cos(2*pi*u))/2` 度，`u=(frame-start)/(end-start-1)`；两腿反向绕髋摆动，双臂反向配合，端点外为零。采样无历史、无随机性。

示例：`examples/stage-motion.json`（18 秒，靠近、点头/挥手、挥手/鞠躬三个镜头）。可选 `scripts/export_video.py` 把同一 Python 后端逐帧 SVG 编码为 MP4；这是离线演示导出，不增加核心运行依赖，也没有音频。
